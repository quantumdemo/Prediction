# Data Lineage & Provenance Architecture (Stage 4)

## Principles

The Football AI Intelligence & Machine-Learning Platform enforces full data provenance and auditability. Every prediction generated by future forecasting engines must be traceable back to the exact source URLs, raw API responses, ingestion timestamps, and dataset snapshot version.

## Lineage Architecture Diagram

```
[EXTERNAL SOURCE API / REPO]
           │
           ▼
[1. RAW SOURCE PAYLOAD] (raw_source_payloads)
  - Stores unparsed JSON response
  - External ID + Source ID
  - Retrieval UTC timestamp
           │
           ▼
[2. NORMALIZED ENTITY] (matches / clubs / match_statistics)
  - Canonical Entity UUID
  - Controlled Validation State (VERIFIED / LIKELY / CONFLICTING)
           │
           ▼
[3. PROVENANCE RECORD] (provenance_records)
  - Entity Type + Entity UUID
  - Source ID + Immutable Source URL
  - Retrieval UTC timestamp
           │
           ▼
[4. DATASET SNAPSHOT VERSION] (dataset_versions)
  - Dataset Version Label (e.g. 'v2025.1-cutoff-20250916')
  - Strict Cutoff Timestamp UTC (Zero future-data leakage guard)
```

## Zero Future-Data Leakage Rule

Model feature matrices for backtesting and training must reference a specific `dataset_versions` record. Any match event or statistic recorded after `dataset_versions.cutoff_timestamp_utc` is strictly excluded from feature computation.
